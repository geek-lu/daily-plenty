INTERACTION MAP / 交互地图

少一点操作，多一点日常。

以手机单手记账为核心。金额先行、默认值减负、模板只预填；把确认留给人，把重复交给系统。

01 / 入口

随手打开账本

首页与手机底部均有「记一笔」。午餐、通勤、咖啡模板可直接预填。

02 / 必填

先输入金额

调起数字键盘。默认支出、今天、当前用户付款；分类可直接点选。

03 / 核对

一屏就能完成

备注可选，付款人可改为 TA。无需先选资金账户或上传截图。

04 / 完成

保存，回到日常

关闭弹层并更新概览。批量补记时，选择「保存，再记一笔」。

减少输入，不减少确认

  • 普通记账：输入金额 + 选分类 + 保存。
  • 模板记账：金额、分类、备注预填；用户核对后保存。
  • 连续记账：保留付款人和日期，清空金额、备注。
  • 录入人固定来自登录身份，与付款人分开存储。

原型中可以实际试用

  • 新增收入 / 支出、快捷模板、连续录入。
  • 按月份、付款人、收支类型及备注筛选。
  • 点开账单编辑、删除确认、删除撤销。
  • 分类统计、双方付款统计、导出演示 CSV。
01 / 创建者

创建共同账本

首次初始化创建者账号，设置小家名称；不开放任意用户注册。

02 / 邀请

分享一次性链接

创建者主动复制链接给伴侣；链接建议 24 小时有效，可撤销。

03 / 加入

确认「我们的小家」

对方设置账号密码，确认加入。事务内验证有效期和两人名额。

04 / 共用

各自记账，一起查看

服务端是数据源；回到页面或手动刷新后拉取最新账单，不承诺即时推送。

本流程为正式产品设计，当前 HTML 没有真实账号、邀请链接或跨设备共享。
01 / 校验

金额不合法

零、负数、超过两位小数不能保存；错误显示在表单内，不清空内容。

02 / 提交中

保存按钮暂不可点

正式产品生成唯一请求标识；按钮显示「保存中」，阻止双击提交。

03 / 断网或超时

保留输入，可重试

显示未保存状态，保持当前页草稿；重试使用同一请求标识，避免重复记账。

04 / 服务端确认

成功才进入账本

已落库但响应丢失时，重试返回原记录；第一期不做离线提交队列。

本原型可验证金额错误提示；网络失败、鉴权、幂等与服务端冲突仅为设计，没有用假动画模拟真实联网。
01 / 找到记录

点开一笔账单

按月份、付款人或备注定位。原值完整回填，不要求重新输入。

02 / 编辑

改金额或付款人

创建人保持不变，记录最后修改人。正式产品带 version 提交，防止覆盖对方修改。

03 / 删除

明确二次确认

提示具体账单和金额，确认后软删除，提供短时间撤销入口。

04 / 冲突处理

先看对方的新版本

版本不匹配返回 409，保留本地输入；用户查看新记录再决定如何修改。

原型实现本地编辑、删除和撤销；版本冲突与软删除恢复将在正式服务端实现。

从成熟产品中借鉴什么

调研状态：当前环境无法联网，以下依据既有产品认知整理，尚未核实各产品当前版本的界面、功能及收费。交互流程是本项目提案，不是竞品实测结果。
参考方向 产品定位 / 待核实 日日有余的取舍
钱迹 简洁记账与分类管理 金额优先、分类直达，首页聚焦记录。
Honeydue 伴侣共同管理财务 独立身份、一个共享账本；付款人与录入人分开。
YNAB 预算分配与规划 可选月预算提示，不引入完整预算分配体系。
Splitwise 共同支出与分摊 展示各自付款，第一期不自动算欠款。

核查入口： 钱迹 · Honeydue · YNAB · Splitwise 。详细限制见目录内 RESEARCH.md。
