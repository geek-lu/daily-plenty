## 快速录入方案（本项目提案，非竞品实测）

常规：记一笔 → 输入金额 → 选择分类 → 保存。
快捷模板：点击午餐/通勤/咖啡 → 金额和分类预填 → 核对保存。模板不直接提交，避免误触入账。
默认：支出、今天、当前用户付款。连续记账保留付款人和日期，清空金额和备注。
备注可选；不先强迫选择资金账户、账本、标签或上传凭证。
原型设置三个模板，正式产品再决定是否允许自定义，不默默增加配置功能。

## 共享与错误交互

创建共同账本 → 生成有时效的一次性邀请链接 → 对方登录 → 确认加入；默认最多两位成员。
保存时禁用重复提交；失败保留输入；超时用同一个请求标识重试，服务端防止重复写入。
乐观反馈只显示“正在保存”，服务端确认后才能显示“已保存”。
第一期联网保存；断网保留当前页草稿，不承诺后台离线队列或跨设备草稿同步。

## 范围

第一期：独立登录、双人账本、收支录入/编辑/删除、付款人、月度筛选/统计、CSV 导出和备份。
后续讨论：关联原支出的退款、资金账户与转账、预算编辑、导入历史账单、离线队列、OCR。
不在本轮：银行同步、支付平台自动抓账、付费 AI、原生 App、订阅管理。
月预算 6000 元只是原型示意；是否加入正式版本以及具体额度均待评审。

## 数据设计补充（2026-11-09）

首期界面仍为双人共享账本；正式数据模型使用 User / Ledger / Membership 多对多关系，人数限制放在服务端策略。
分类独立建表并初始化默认值，自定义分类界面后续评审；内存 HTML 原型的固定分类不等于正式表结构。
账单以整数最小货币单位和币种表达金额。首期只允许人民币，后续多币种需明确新增汇率与折算口径。
退款、转账、附件等采用独立实体与明确关系按需迁移；不提前创建空扩展表。详细约束和演进路径见 architecture.html 的「数据关系」。
